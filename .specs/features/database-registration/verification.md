### Level, sampling and precision notes

None of these fails a row. Each is recorded so a reader knows what the green proof does not
cover.

1. **C11, level (recorded, not a gap).** The race is two `DatabaseRegistrationFiles.create` calls interleaved on one Node event loop, not two `vestra database add` processes. The claim is worded at the store layer, which `checks.md` declares, and it names the store's `{ created: true }` and error code, not an exit code, so by definition this is not a level gap. The exclusion is an OS-level hard link that fails on an existing name (`apps/vestra-cli/src/database/database-registration-file.ts:282-291`), so it does not depend on having a single process. AC 8's command-level race (exit 5 for the losing `add`) is not exercised as a race; the sequential conflict mapping is C9.
2. **C18, sampling (recorded, not a gap).** The store-level order assertion (`:309`) has two members, `billing` and `orders`. Locale order would sort them the same way, so on its own it does not tell code-unit order apart. The store's `list` is built on `DatabaseRegistrationFiles.entries()` (`database-registration-file.ts:342`), which sorts with `codeUnitCompare` (`:259`). That is the same function C12 checks with discriminating ids (`-` < `.` < `_`, `tests/contract/database-command.test.mjs:470-484`).
3. **C13 and C17, platform precision.** On win32 the `linked.json` entry is a junction to a directory, which would read `invalid` even if it were followed. "Not followed" is told apart only on Linux, where it is a symlink to a registration that would verify. The WSL run carries that evidence.
4. **C21, scope.** The scan covers the family's direct import statements. Transitive edges are out of the claim's scope: the Git runner the family reaches through `task-workspace.ts` uses `node:child_process`. C22 is the runtime sensor for the processes actually started. No check observes sockets at runtime; "contacts no database" rests on C21's import rule plus C22.
5. **C26.** The `--help` test existed before this feature. The diff changes the expected value the test asserts (`tests/e2e/cli-launchers-e2e.test.mjs:45`), so the proof is about the new behaviour.
