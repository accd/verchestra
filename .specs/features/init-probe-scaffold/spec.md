# Init Probe Scaffold Specification

Issue: #234. Decision: AD-035 in `.specs/STATE.md`, which applies the
post-1.0 half of AD-017. The owner chose to implement it now. It changes no 1.0
claim and does not alter the recorded 1.0.0 hold.

## Problem

AD-017 has a team implement the published connection port for its engine in
its own repository and run the conformance kit in its own CI. Nothing helps it
start. The published kit (`tests/helpers/*-probe-fixture.mjs`) imports this
repository's sources, and `@verchestra/data-probe` is private, so a team
repository cannot import either.

## Scope

- `vestra init` gains `--probe-engine <engine>`, `--probe-language typescript`,
  and `--probe-dir <path>`.
- The scaffold for the chosen engine goes through the same `SafeInitService`
  preview and apply as the canonical workspace files.
- Out of scope: completing the scaffold with AI. That is a normal delivery
  task through the governed task command (#405), documented as a follow-up
  and not built here. Languages other than TypeScript wait for the
  out-of-process host (#235).

## Requirements

| ID | Requirement |
| --- | --- |
| IPS-01 | `--probe-engine` accepts exactly the eight published engines: `postgresql`, `mysql`, `mariadb`, `sqlserver`, `sap-ase`, `oracle`, `sqlite`, `mongodb`. `--probe-language` accepts only `typescript`. |
| IPS-02 | The scaffold is byte-deterministic for a given (engine, contract version). It embeds no clock and no product version, files are sorted, LF-only, and ASCII. The directory changes only the paths. |
| IPS-03 | `--probe-dir` defaults to `.verchestra/probes/<engine>` and accepts only a portable lowercase path of at most four segments under `.verchestra/probes/`. Anything else is `VES_CLI_ARGUMENT_INVALID` before any write. A probe option without `--probe-engine` is also refused. |
| IPS-04 | The files flow through `SafeInitService`: `--dry-run` writes nothing, apply writes exactly the generated bytes and records them in the ownership manifest, a repeat is a no-op, and a file the team has changed is never overwritten. |
| IPS-05 | `contract.mts` holds a copy of the engine's published port and its supporting types. Each copied type is identical to the published one, and a test fails on drift. |
| IPS-06 | `connection.mts` implements the port. Every method throws `ProbeDriverTodoError` with the stable code `VES_PROBE_DRIVER_TODO` and carries a `TODO(driver)` comment. Candidate driver packages appear only in comments. |
| IPS-07 | `conformance-kit.mts` drives the connection through the same session calls as the published adapter and reaches the same principal and session verdicts. Identity, product, row-shape, and row-limit violations each fail with a distinct `VES_PROBE_KIT_*` code. |
| IPS-08 | The kit run against the generated connection fails with `VES_PROBE_DRIVER_TODO`, both in process and through `node --test`. It never passes vacuously. |
| IPS-09 | The generated TypeScript typechecks under the repository's strictness with NodeNext resolution, passes the repository's ESLint configuration, and is already in the repository's Prettier format. |
| IPS-10 | No dependency is added to the team's repository. Generated files import only each other and `node:` built-ins. |
| IPS-11 | The generator uses no AI, makes no network call, and needs no configured Driver. |
| IPS-12 | The CLI manifest advertises the three options with exactly the generator's engine and language lists, without importing `@verchestra/workspace` into the doctor's read-only closure. |

## Design notes

- Files are `.mts`, so they are ES modules whatever the team's `package.json`
  `type` is, and they run under Node's native type stripping.
- The generator lives in `packages/workspace/src/init/`, which the CLI already
  depends on. No package edge and no lockfile change.
- Generated import lines are built by one helper that mirrors Prettier's
  layout. This keeps output stable under the team's formatter, and keeps
  literal import lines out of the generator's source, where the repository's
  textual import-closure guards would read them.
